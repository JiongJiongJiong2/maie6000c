## 限额与迁移

普通导入的单文件上限为 10 MiB 与目标库 `MAX_CANDIDATE_BYTES` 的较小值。备份还原使用目标库的 `MAX_CANDIDATE_BYTES`，默认 25 MiB。服务端在建立清单及读取 multipart 前按数据库中的批次用途选择同一规则，multipart 信封另允许最多 16 KiB。相同客户端键和清单可以重放，变更用途返回 409。ZIP 的原文件总量与条数限制继续适用。

Alembic `20261118_0007` 从 `20261117_0006` 升级，将既有批次标为普通导入。旧清单摘要、回执和状态保留。升级前因普通导入上限遭拒的旧还原项保留原状态，从备份清单重新发起还原会创建新的还原批次。

## 正式网页往返

在独立的 PostgreSQL 源库和空目标库上启动两套真实 API，使用 Chrome 打开正式 `/web/`。源库使用确定性随机像素生成 38 帧、512×512、13,691,729 字节的 GIF，并经服务端完整动画校验。源库网页从原 GIF 备份下载 ZIP，本地解包并选择清单与 GIF。

目标端故意中断第一次 PUT。重开页面，重选同一 GIF 后通过「继续上传」完成原批次。再发起备份还原，命中已保存资产并恢复标题 `Large original`、手动标签 `roundtrip` 与手动 OCR `preserved`。目标库最终仅有一项，帧数仍为 38。
