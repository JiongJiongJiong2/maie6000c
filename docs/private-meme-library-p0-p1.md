## P1 跨库验收通过

网页一次最多选择 60 张 GIF，按 20 张拆批。各批显示待传、成功、重复和拒绝，续传按 SHA 和大小匹配用户重新选择的文件。筛选支持标题、标签、状态。选中状态可跨筛选保留，支持批量追加手动标签、展开疑似重复原图、备份全部选中项。

备份格式为 `original_zip` v1，最多 60 张、原 GIF 合计最多 256 MiB。ZIP 包含 `assets/<sha256>.gif` 和 `manifest.json`。清单含标题、SHA、帧数、字节数、现有来源以及可选手动字段和已保存识别。源库原表没有独立的授权说明字段。还原时由用户本地解包，浏览器校验后经原导入 API 保存，再按 SHA 还原元数据。已有人工字段优先。已识别结果可从包内恢复，无需新发模型请求。

| 检查 | 实测结果 |
| --- | --- |
| 30 个文件的正式网页导入 | 两批 20 和 10。分别注入一次请求中断，刷新后只重试这两项。最终 23 唯一资产、6 精确重复、1 坏 GIF |
| 两套 PostgreSQL 间备份还原 | 下载原 GIF ZIP 至本地，目标为空库。首轮逐项报告 1 缺失、1 SHA 不符。补齐后 23 项还原，原字节 SHA、帧数、标题和批量标签一致 |
| 重复还原 | 目标最终仍为 23 项。自动化集成还覆盖了可选标注版本、原采样帧和手动 OCR 覆盖的往返 |
| 耗时 | Chrome 自动化流程，源库操作和下载 6.987 秒，目标库两次还原 5.505 秒。真人整理耗时待试用记录 |
| 正式 API 镜像 | 从最终代码构建并启动容器，`/web/` 与 `/web/library.js` 均为 200，类型为 HTML 与 JavaScript |
