## 完成目标

> 在同一个可复现的候选版本上，用一张有独立目标凭证、目标 GIF 起初不在本地的截图，从正式 `/web/` 完成本地检索、主动联网续搜、原 GIF 播放与下载、确认收藏和索引就绪。重启 API 与 worker 并禁用外部供应商后，以新请求从本地找回同一资产，下载原件的 SHA-256 与首次联网取得的原件一致。随后完成真实需求 A/B/C 对照、真人判分、四位成员独立复现和 W13 材料，提交团队评审。团队验收后另行确认 `dev → main`、期末标签及课程提交。

工程闭环、检索效果和期末签收各自有完成条件。已有 PR 的自动化回归和真实运行记录继续用作各自版本的证据。本页的新版本验收项在对应证据齐备后填写结论。来源不可达、缺少授权或需要真人签字时，保留实际状态及已取得的证据，由相应负责人解决或确认后续范围。

## 正式网页闭环

11 月 27 日已用 DeepSeek 的 GIF 续搜 API 完成本地未命中、联网取得 44 帧原 GIF、收藏和建索引。重启并阻断对外连接后，全新 Chrome 会话在 `/web/` 以另一帧首位命中同一资产，网页下载与原件 SHA-256 一致。成功复测在隔离 worker 内对两个 Commons 域名使用真实公共 DNS，原系统 DNS 的失败也已留档。正式网页的 `meme50-v2` 续搜按钮仍待同流程实测。[DeepSeek 与离线复用实测记录](evidence/gif-acquisition/deepseek-offline-reuse-20261127.json)

先记录代码提交、有效配置指纹和隔离环境。选用可以测试和保存的真实媒体，独立保留目标来源、原 GIF 的 SHA-256 和帧数。确认目标资产起初不在固定库或私人库中，再从 `/web/` 选「仅本地检索」上传截图。原任务应正常完成，且未命中该目标。

从同一页面点击「继续联网搜索」。原 `request_id` 和本地 `job_id` 保持可查，联网任务有独立 `job_id`，刷新后仍可看到本地结果及联网进度。当前页面经 `meme50-v2` 使用 HKUST 视觉、DeepSeek 查询规划和网页检索。用实际任务记录供应商调用、来源、结果 revision 及停止原因。历史 DDGS 路径可用于定位 legacy API 问题，其证据按 API 实测记录。[当前供应商说明](hkust-deepseek-execution.md)

在正式网页播放候选原 GIF 并下载，对照动画帧数及候选、下载文件、数据库三处的 SHA-256。点击「确认并收藏」，记录确认回执、资产 ID 和索引由待处理到 `ready` 的状态。刷新页面后确认仍能下载原件。保留数据库与媒体目录，禁用外部供应商并重启该验收环境中的 API 和 worker，再提交新本地任务，核对同一资产 ID 和原件 SHA-256。用回执、只读数据库核对及浏览器截图或录屏佐证，交付记录只保留可分享的数据。

一次闭环可验证系统联通与持久化。取自目标 GIF 的抽帧可以检查工程链路，并在证据中标记为派生输入。实际用户截图及独立目标判断另用于效果评估。失败任务记录确切阶段、错误类别和后续操作，同样保留 ID 与日志。

## 效果评估与功能边界

按项目原计划收集至少 30 个真实截图需求。登记授权、输入 SHA、目标来源和独立判定，区分库内目标、库外已知目标和目标未知。按 GIF 或梗图家族隔离开发与最终验收集。A 组只跑本地检索，B 组加入直接描述搜索，C 组加入查询规划与最多一次补搜。B、C 使用相同来源、搜索调用预算及媒体下载上限。开发集完成一轮改进后，预先冻结运行参数、判分和质量门槛，最终验收集全部计入相应分母。报告 Top-3 原 GIF 命中、动画和下载可用性、收藏后复用、端到端耗时、外部调用数和失败类型。同款替代与目标未知单列。[项目评价协议](final-project-plan.md)

如果期末材料将 `meme50-v2` 的多结果能力列为交付指标，在同版补齐其既有 A0–A8 证据。三例资源充分案例各单次返回 40–50 条，至少 12 例家族隔离留出集接受真人审阅，Top10 明确相关宏平均至少 90%，实际返回列表至少 80%，内容重复为零。以实际运行、下载和真人标签为准。对接 WhatsApp、微信、QQ 的原生动画或贴纸导入保留独立验收，网页原 GIF 分享按实际设备、浏览器和结果报告。[联网验收标准](hkust-deepseek-execution.md#验收范围修订)
