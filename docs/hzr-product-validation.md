# 给 HZR 的痛点验证备忘

**第一轮建议找做过动态贴纸交付的设计师或素材负责人。** 请对方还原最近一次客户拿截图要旧稿的经过。我们想知道这类请求出现得多不多，以及拿错字幕、语言或客户版本会造成什么后果。选这个场景，是因为对方可以拿已批准的交付文件作参照，团队也能用现有网页走完整个任务。目前这个选择仍是待验证的假设。

## 四种场景，四种完成标准

| 场景 | 用户怎样才算完成 | 工程已有的部分与 HZR 要确认的缺口 |
| --- | --- | --- |
| 设计工作室收到旧稿截图 | 经手人找到该客户已批准的那一版，按要求交付，收件方能播放 | 私人库已有批量导入、手动标签、近似项预览和原件下载。请经手人拿一组动作相同、字幕或客户不同的文件，演示今天怎样认定批准版。[私人库验收](private-meme-library-p0-p1.md) |
| 品牌或 IP 的贴纸被转发 | 用户从单张截图认出所属贴纸包，并进入对应平台的官方领取页 | 可复用截图检索。香港反诈骗协调中心确实发布了 20 款 WhatsApp 和微信贴纸。还需品牌方提供贴纸与官方入口的映射，并确认实际有人在失去来源后回来找整包。[香港警方活动页](https://www.adcc.gov.hk/zh-cn/quby-anti-scam-campaign.html) |
| 群聊用户找自己的梗 | 用户想起某张图，找到它并发出，对方手机上能看到动画 | 已有私人标签和原件下载。研究发现群聊关系和共同背景会影响 GIF 选择。仓库记录的一次 iPhone 实测中，网页分享到微信后变成静图，改走微信内长按才成功。请观察用户愿意花多久找和发，以及何时换图或放弃。[24 人访谈研究](https://arxiv.org/abs/1903.09623) · [微信真机记录](wechat-gif-sharing-investigation.md) |
| 社区产品在发帖框嵌入素材选择器 | 成员搜出社区准许使用的素材，插入帖子，其他成员看得到 | 可复用检索与原件读取。先找一位同时能提供自有图库和真实发帖入口的社区维护者，观察现有发布步骤，再决定是否投入接口适配。[现有工作流](../submissions/week13/README.md) |

## 工作室这条线怎样验收

工程主流程先做到同事可以独立复演。导入一组可使用的原 GIF，上传一张截图，从候选中选中并下载指定文件。保留原件，重启服务后换一帧再搜，核对两次下载的 SHA-256。仓库已有这一流程的浏览器记录。**哈希能回答“文件对不对”，经手人才能回答“这版能不能交给这个客户”。** [发布版验收](../submissions/week13/README.md)

HZR 可以先约一位经手人，用一次已完成项目的脱敏截图、已批准原件和一份容易混淆的稿子跑一遍。测试前由对方私下记下正确版本和交付要求。操作时只给截图和当时客户实际给出的线索。先观察对方用原来的方法，再用难度相近的另一题试我们的网页，记录搜索用时、选了哪版、需要谁帮忙、导出后能否播放。另放一张库里确实没有的图，观察是否误交相似稿。如果卡在“批准状态无从查”，先让对方用已有标签标记客户和版本再试。如果搜索很快却导出失败，下一轮就只补交付那一步。公开图库的批量试验衡量检索，用户实试单独记录。[检索评测协议](retrieval-benchmark-at-scale.md)

## 访谈时直接问

“最近一次有人让你找旧动图是什么时候？对方发来了什么，最后拿走了什么？” “能按当时的顺序给我看一遍吗？哪一步最费时？如果很快就找到了，也想看看为什么。” “你凭什么认出是正确版本？如果只能找到一张相似的，通常怎么处理？” “过去四周能想起几次？最终谁确认能交？上一次交错或没找到时，后来怎么解决的？” 记录一例顺利的、一例麻烦的，以及没有遇到过的人。发生过的返工、等待或放弃，比对新功能的口头兴趣更能帮助团队取舍。

**可以直接回复 HZR**

> 我们这边先把工程跑完整，让别人拿一张截图也能找到、核对、拿走正确的原动图。你可以先帮我们问问做过贴纸交付的人，上一次客户拿截图找旧稿，他们到底卡在哪一步。最好带回来一个实际例子，顺利找到的也行。等我们把这件事从头走一遍，缺检索就补检索，缺版本判断就补版本判断，最后看客户能不能拿到能用的那一版。
