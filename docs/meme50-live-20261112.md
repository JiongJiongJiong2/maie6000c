# HKUST / DeepSeek 真实验收进展

本记录补充旧验收报告。当前服务范围以 `hkust-deepseek-execution.md` 为准：学校看图、DeepSeek Flash 查询规划与官方网页搜索；像素反搜明确禁用，不再等待 Google Vision 或 Brave。总状态尚未通过完整验收。

## 已实测的链路与故障修复

真实的 PostgreSQL、API、独立 worker、隔离 public fetcher 均保留原数据运行。空文字上传不传文件名语义或目标 URL。首轮五条任务先等页面抓完才下载，首批约 135.5 秒；改为有限页面波次、跨查询分配页面预算后，另一次任务首批约 28.6 秒、约 37.3 秒结束。两次独立任务不是严格性能基准，搜索内容有差异。

真实来源发现了 JPEG 大小图、透明切图和同帖媒体版本重复。当前实现增加明确的 ReactionStash 帖子身份、局部像素校验，以及多帧时序证据；循环或起始帧变化可合并，字幕变化、反向动作、低信息双色动画保守保留。较大裁剪差异仍可能漏合并，不能把算法 content_group_id 不同当作真人确认的不同内容。

Tenor 页面公开的相关推荐现在仅在提供其自身实际 permalink 和媒体地址时进入独立候选；每页有数量上限，最终仍受全局下载、字节、时间和排序门槛约束。不读取嵌入页面的 API 配置，不编造 CDN 地址，不把推荐素材归属于主帖。排序门槛仍为 0.55。

## 开发实体检索诊断与 v8

v7 三个资源案例真实单次结果为 Homer 50、Pepe 50、Tom/Jerry 23。最后一例数量未通过，不用预筛库存补齐。开发诊断发现：核验查询先拼接三段长观察再加实体名，截到 DeepSeek 的 128 字符上限时名字被全部截掉；规划器也可能将宽泛角色查询排在精细动作之后，耗掉页面/媒体预算。

修复只使用实际看图输出：将实体假设放在核验查询前部；优先保留一条宽泛视觉实体检索，其他动作/情绪角度保留。高置信且 supported 的实体可补该角度；uncertain 名字只有规划器自己已提出对应名字查询时才放宽，状态仍 uncertain，不将假设写成确认身份。trace 区分模型原始查询、派生角度及假设状态；不读测试标签、文件名或预筛 URL。

独立开发修订尝试分别 32、41 条，各自原始 job 和代码快照保留，不与正式结果混合，不将不同实时搜索结果当作严格因果收益。查询策略最终为 `query-plan-v4-hypothesis-priority`，仍限制 3 模型调用、6 总查询、40 页面、120 媒体尝试及原时间/字节预算；相关性权重和 0.55 门槛未降低。最新 Python/PostgreSQL 联合回归 344 项通过，2 项既有 smoke 未选中。

当前完整运行清单为 `meme50-evaluation-v8.json`，输出 `frozen-v8/`。三资源和十二冻结输入全部重新执行；v7 和之前失败仍保留，不能把历史混成一份同版本成功。正式浏览器、真人标签和成员复现按当前具体产物判定。
