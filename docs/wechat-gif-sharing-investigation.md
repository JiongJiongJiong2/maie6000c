# 微信 GIF 分享排查（2026-11-15）

目标：iPhone 上不安装辅助 App，发送后在微信聊天气泡内播放动画。目前尚未修复，不以下载、附件、视频或手动收藏代替这一目标。

## 已有真机结果（用户反馈）

- iPhone 12、iOS 16.3.1、Safari：网页系统分享至微信后是静态图片；Mind blown 和 Party time 均失败。
- 原 GIF 下载后可播放，分享至 WhatsApp 可播放。
- 下载到“文件”→保存至“照片”→微信导入自定义表情→发送，可以播放。这是有效对照，但不是网页直接分享修复。

## 本轮代码和服务核查

`web/share.js` 使用下载得到的原始 Blob 创建 `image/gif` 类型、`.gif` 文件名的 File，再调用 `navigator.share({ files: [file] })`。没有转成 PNG、JPEG，也没有提取首帧。

Web Share 的公开参数没有指定微信表情消息类型的选项；成功返回不能证明接收方保留动画。参见 https://www.w3.org/TR/web-share/ 。当前证据无法进一步断定是 Safari 的交付方式还是微信分享扩展的处理导致静态化。

## 微信内原图发送真机对照（用户已确认会动）

测试微信内置浏览器对原始 GIF 的图片操作，绕过 Safari 的系统分享扩展：

1. 把原图 HTTPS 链接发送给自己，在微信会话中点击，用微信内置浏览器打开。
2. 确认原图播放后，长按图片，记录是否提供“发送给朋友”或“添加到表情”。
3. 若提供“发送给朋友”，发送给自己，并确认新消息聊天气泡内是否播放动画。
4. 若只有“添加到表情”，另行记录此路径；它不能算直接发送通过。若只提供保存图片，或发出仍静态，此候选路径未解决问题。

用户按上述原图链接流程操作后反馈：“按你这么说的做就会动”。本次 Party time 的微信内打开原图、长按发送路径通过用户真机验证。未取得发送过程录屏、收件文件或文件哈希；不能把结果外推到全部 12 个 GIF、其他手机或微信版本。

结论：找到了保留动画的替代发送路径，原 Safari 系统分享按钮仍未修复，也没有实现一键导入到表情收藏。用户随后明确拒绝在正式页面加入这个手动入口，要求继续只研究一键发送。保持正式分享代码不变，没有增加辅助 App 或调整公共接口。

## 一键发送接口继续核查

2026-11-15 直接读取了微信官方托管的 JS-SDK 1.6.0 源码：
https://res.wx.qq.com/open/js/jweixin-1.6.0.js

其中 `updateAppMessageShareData` 传入 title、desc、link、imgUrl。这个公开接口提供分享标题、描述、链接和图标，没有传入 GIF 文件或指定原生表情消息的参数；`previewImage` 也不能视为直接发送。不能通过更换分享图标为 GIF 就宣称聊天气泡支持动画。此次检查仅针对实际读取的这一 SDK 版本，不以搜索无结果证明所有微信能力都不存在。

另外直接读取了微信小程序官方文档（HTTP 200）：
https://developers.weixin.qq.com/miniprogram/dev/api/share/wx.showShareImageMenu.html

该接口自基础库 2.14.3 开始提供图片分享弹窗，要求本地或临时文件路径；官方示例先 `wx.downloadFile`，再传 `tempFilePath` 给 `wx.showShareImageMenu`。因此它是一条可以研究的“小程序内调用图片发送菜单”的路线，普通 Safari 网页不能直接调用它。文档没有明确承诺 GIF 动画保留，当前没有小程序真机验证结果，不能宣称能够解决本问题。图片分享弹窗仍需要用户选择收件人并确认发送。

采用该路线需要增加独立小程序端及相应开发/预览配置，属于接入方式改变。尚未改动现有检索、API、数据库或网页；尚未创建小程序或安装开发工具。
